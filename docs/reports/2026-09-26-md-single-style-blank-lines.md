# `single` 段落样式下的空行逻辑

日期：2026-09-26
插件版本：3.20.9（空行规则的来源，见 CHANGELOG 3.20.9）
代码：`plugin/Markdown/utils/helpers.py` 的 `apply_paragraph_style()`
（判定链 `_classify_lines()` → `_keeps_a_blank_line()`）

本文只讲 **single（每行一段）** 样式下空行的取舍逻辑：`block` 样式原样返回，不做任何事。

---

## 1. 一句话

对整份文件做**减法**：删掉段落之间的空行，让每行自成一个段落行；**不是**段落分隔的空行留下；
同一处的空行串合并成一个；`blank_line_before_heading`（默认开）时在 `#` 标题前补一个空行（文件
第一行不补）——这是唯一新增空行的地方。除此之外一个空行都不加。

调用点在 `EnhancedMarkdownMLizer.extract_content()` 的最后一步：作用于拼好的整份文件
（YAML 文首 + 封面 + 目录 + 正文 + 脚注），在 `tidy_up`、清不可见字符、折行之后。因为输入是
block 模式的文本（每个块边界本来就有空行），本步是「留还是删」，不是「补」。

## 2. 判定分两步

### 2.1 `_classify_lines()` —— 每行是什么

每行得到 **结构种类** 与 **是否引用行**：

| 种类 | 判据 | 例子 |
|---|---|---|
| `_FENCED` | 围栏代码块内（含围栏行本身） | ` ```python `、围栏内的空行 |
| `_LIST` | 行首（剥掉 `>` 前缀后）是列表项，或列表项之后的缩进续行 | `- 甲`、`1. 甲`、`\t- 子项`、`\t条目的第二段` |
| `_TABLE` | 以 `|` 开头且属于一张有**对齐行**的表 | `\| a \| b \|`、`\|---\|---\|` |
| `_CAPTION` | 正文行，但它下面（空行之后）就是表格首行 | `*表标题*` |
| `_DEF_TERM` | 正文行，它的下一行是 `: 释义` | `术语` |
| `_DEF_ITEM` | 行首是 `: ` | `: 释义` |
| `_FOOTNOTE` | 行首是 `[^n]:` | `[^1]: 脚注正文` |
| `_QUOTE` | 引用行（含引用之后不带 `>` 前缀的 lazy 行） | `> 引文`、`> - 甲`、引用里 `<pre>` 的代码行 |
| `_TEXT` | 其余 | 段落、标题、`* * *`、行内 HTML 行 |

三个细节，都是实测逼出来的：

- **表格必须有对齐行**（首行 + `|---|`），否则只带竖线的正文行不算表格；
- **`* * *` 先按分隔线认**（渲染器写 `<hr>` 就是它），不当列表项——分隔线本身不需要空行；
- **引用行之后不带 `>` 前缀的正文行仍算引用**（渲染器写引用里的 `<pre>` 时不带前缀），
  因为引用是读到下一个空行为止。

### 2.2 `_keeps_a_blank_line(previous, following)` —— 这个空行留不留

只看空行两侧的**内容行**，判定顺序即语义（第一条命中即返回）：

| 上一行 | 下一行 | 结果 | 理由 |
|---|---|---|---|
| 引用行（含 lazy 行） | 引用行 | **删** | 引用内部的空行是引用的段落分隔 |
| 引用行（含 lazy 行） | 非引用行 | **留** | 它是引用的终止，删了下一行被吞进引用 |
| 结构（列表/表格/标题行/术语/释义/脚注定义） | 任意（非引用内） | **留** | 块后面的空行是块的一部分 |
| 任意 | 结构 | **留** | 块前面的空行是块被识别的前提 |
| 正文 | 引用行 | **删** | 引用能打断段落 |
| 正文 | 正文 | **删** | 这就是段落分隔 |

`_STRUCTURE_KINDS` = 列表 / 表格 / 表格标题行 / 术语行 / 释义行 / 脚注定义行。
**「上一行是引用行」排在最前**，这就是「引用内部一律不动」的实现（§6）。

### 2.3 主循环里的另外两件事

- **合并**：连续空行只留一个（`not kept or kept[-1].strip()`）；`_FENCED` 行整段原样写出，
  围栏内的空行串不动。
- **插入**：`blank_line_before_heading` 且上一行有内容且本行是 ATX 标题 → 补一个空行
  （`kept[-1].strip()` 保证不会补出两个）。

## 3. 留（9 处）

| # | 位置 | 不留会怎样 | 谁需要 |
|---|---|---|---|
| 1 | 围栏代码块内（原样） | 代码内容被改 | 两边都要 |
| 2 | 引用块结束处 | 下面一行被吞进引用（lazy continuation） | 两边都要 |
| 3 | 列表块前后 | 后一段被读成最后一个条目的续行；python-markdown 不认段落里的列表 | 两边都要 |
| 4 | 列表条目内部（条目第二段的「空行 + 缩进」） | 条目两段并成一段 | 两边都要 |
| 5 | 表格块前后（含上方 `*标题*` 行与表头之间） | 后一段被读成表格的一行（GFM Example 202）；python-markdown 不认段落里的表格 | 两边都要 |
| 6 | 定义列表前后 | 前一段读成 `<dt>`、后一段读进 `<dd>` | python-markdown（GFM 无此语法） |
| 7 | 脚注定义块前 | 定义被并进正文（防御性，python-markdown 实测不必须） | 留着更稳 |
| 8 | 结构下方紧跟引用行（`- 项` / 表格行下面的 `>`） | 引用打断得了段落、打断不了列表项，那行 `>` 被读成条目的续行 | 两边都要（真书 394） |
| 9 | 引用之后不带 `>` 前缀的 lazy 行后面的空行 | 它是引用的终止，删掉会把下面整段正文吞进引用 | 两边都要（真书 427） |

## 4. 删（6 处）

| 位置 | 说明 |
|---|---|
| 段落之间 | 含缩进续行、图片行、行内 HTML 行——「每行一段」靠读者/读取器自己分段 |
| 引用块内部 | 引用是"自己的文本"，它内部的空行是引用的段落分隔 |
| 围栏代码块前后 | 围栏能打断段落（CommonMark §4.5） |
| `* * *` 前后 | 分隔线能打断段落（CommonMark §4.1） |
| 进入引用处（正文行 → 引用行） | 引用能打断段落（CommonMark §5.1 Example 223） |
| 标题前（选项关闭时） | ATX 标题能打断段落（CommonMark §4.2） |

## 5. 插（1 处）

`blank_line_before_heading`（默认开）：每个 `#` 标题前补一个空行，文件第一行的标题不补；
`block` 下无效。

## 6. 引用内部：明确不做

引用里的段落分隔要写成**只含 `>` 的行**（输入侧 `input/paragraphs.py` 的 `_prefix_quote_lines`
就是这么写的）。输出侧不写这种行，因此：

- `> 甲` / `> 乙` 之间的空行照旧删掉（有测试锁住）；
- 引用里的列表/表格结束、后面仍是引用内容时，那行正文会被并进引用里的列表项——block 模式那里
  也只是普通空行，属既有问题，未列入本次范围。

往返不受影响：输入插件读到 single 文件时会按"引用是自己的文本"重新排版，把引用内分段补成
`>` 行。

## 7. 实测依据

- `scripts/probe_single_style_blank_lines.py`：24 种「块结构 + 前后正文」的 block 版过一遍
  `apply_paragraph_style(text, 'single')`，用 **python-markdown**（输入插件读 .md 用的同一个
  解析器）渲染两边比对 HTML → **24/24 一致**（改前 12/24 被破坏）。
- GFM 侧用 markdown-it 复核：表格后跟正文行 → 被当成表格的一行（与 GFM 规范 Example 202 一致）；
  列表后跟正文行 → 被吞进最后一个条目；围栏代码、`* * *`、ATX 标题 → 都能打断段落。
- `scripts/verify_single_style_blank_lines.py`：371 / 394 / 427 / 818 / 17 / 919 六本真书各转
  block 与 single，渲染后比对块结构指纹 → **6/6 一致**，single 版空行明显更少（919：18132 → 96）。

## 8. 已知边界

- **引用内分段**会丢（§6）；引用里 `<pre>` 不带 `>` 前缀（靠 §3 第 9 条兜住引用的终止）。
- **折行先于本步执行**：`max_line_length > 0` 时正文按空格折行，折开的列表续行不带缩进、折开的
  表格行会破坏表格——与本步无关，该功能默认关闭。
- **只做减法**：block 模式文本本身缺空行的地方，single 也不会补。
