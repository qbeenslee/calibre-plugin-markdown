# `single`（每行一段）段落样式的空行逻辑

日期：2026-09-26

本文只描述**规则本身**：一段已经按标准 Markdown 版式排好（块之间有空行）的文本，在"每行一段"
样式下哪个空行留、哪个删、哪里补。不涉及任何实现。

---

## 1. 目标

- 段落之间的空行全部删掉——每个段落行自己占一行，这就是"每行一段"。
- 但**不是**段落分隔的空行必须留下：那些空行是 Markdown 用来认出块结构、或用来结束一个块
  的语法，删掉后文字会被读错位置。
- 一个空行都不新增，只有一处可选例外（§5）。
- 连续多个空行合并成一个。

输入是「块之间本来就有空行」的文本，所以这套规则是**留/删**，不是补。

## 2. 行的种类

按 Markdown 的写法把每一行归到一类（引用前缀 `>` 先剥掉再判断）：

| 种类 | 样子 |
|---|---|
| 代码行 | 围栏代码块内的一切（含围栏行本身与其中的空行） |
| 列表行 | 列表项（`- 项`、`1. 项`），以及它之后的缩进行——条目的续行、条目里的第二段、嵌套列表 |
| 表格行 | 表格首行、对齐行（`\|---\|`）、数据行；**要有对齐行才算表格**，只带竖线的正文不算 |
| 表标题行 | 表格上方那行说明性文字（它下面是表格首行才算） |
| 术语行 / 释义行 | 定义列表：术语行，以及它下面的 `: 释义` 行 |
| 脚注定义行 | `[^1]: 正文` |
| 引用行 | 带 `>` 前缀的行；**以及引用之后不带 `>` 前缀的续行**（引用是读到下一个空行为止） |
| 正文行 | 其余：段落、标题、`* * *`、只带竖线的文字、行内 HTML 行 |

两个容易判错的地方：

- `* * *`（分隔线）不是列表项——分隔线不需要空行，当成列表会凭空多出空行；
- 表格必须"首行 + 对齐行"成对出现，否则正文里出现竖线就会被误当成表格。

## 3. 空行的取舍：只看两侧的内容行

| 上一行 | 下一行 | 结果 | 为什么 |
|---|---|---|---|
| 引用行（含它的续行） | 引用行 | **删** | 引用内部的空行是引用自己的段落分隔 |
| 引用行（含它的续行） | 不是引用行 | **留** | 它是引用的终止；删了下面那行会被吞进引用 |
| 结构行（列表/表格/表标题/术语/释义/脚注定义） | 任意（且不在引用内） | **留** | 块后面的空行属于这个块 |
| 任意 | 结构行 | **留** | 块前面的空行是这个块被认出来的前提 |
| 正文行 | 引用行 | **删** | 引用能打断段落，不需要空行 |
| 正文行 | 正文行 | **删** | 这就是段落分隔本身 |

「上一行是引用行」这条排在最前面——这就是引用内部一律不动、只处理引用边界的实现要点。

## 4. 留下的空行（9 处）与不留的后果

| # | 位置 | 不留会怎样 |
|---|---|---|
| 1 | 围栏代码块内（原样保留，含其中的空行） | 代码内容被改 |
| 2 | 引用块结束处 | 下面一行被当成引用的续行、吞进引用 |
| 3 | 列表块前后 | 列表后的一段被读成最后一个条目的续行；列表前没有空行时，列表根本不被认出 |
| 4 | 列表条目内部（条目第二段的「空行 + 缩进」） | 条目的两段并成一段 |
| 5 | 表格块前后（含表标题与表头之间） | 表格后的一段被读成表格的一行；表格前没有空行时表格不被认出 |
| 6 | 定义列表前后 | 前一段被当成术语、后一段被当成释义的一部分 |
| 7 | 脚注定义块前 | 定义被并进正文（多数解析器不必须，留着更稳） |
| 8 | 结构下方紧跟引用行（列表项、表格行下面那行 `>`） | 引用打断得了段落、打断不了列表项，那行 `>` 被读成条目的续行 |
| 9 | 引用之后不带 `>` 前缀的续行后面 | 那个空行是引用的终止，删掉会把下面整段正文吞进引用 |

## 5. 删除的空行（6 处）

| 位置 | 说明 |
|---|---|
| 段落之间 | 含缩进续行、图片行、行内 HTML 行——"每行一段"靠读的人自己分段 |
| 引用块内部 | 引用是"自己的文本"，它内部的空行是引用的段落分隔 |
| 围栏代码块前后 | 围栏能打断段落 |
| `* * *` 前后 | 分隔线能打断段落 |
| 进入引用处（正文行 → 引用行） | 引用能打断段落 |
| 标题前（可选开关关闭时） | ATX 标题能打断段落 |

## 6. 补的空行（1 处，可选）

「标题前空行」开关打开时，在每个 `#` 标题前补一个空行；文件第一行本身就是标题时不补。
这是整套规则里唯一会新增空行的地方。

## 7. 连续空行

一个位置上的多个空行合并成一个（书籍排版留出的大间距叠在块自身的换行上就会出现）。
围栏代码块内的连续空行不动——那是代码内容。

## 8. 引用块内部：明确不处理

引用里的段落分隔，正确写法是**只含 `>` 的一行**（`> 甲` / `>` / `> 乙`）。本套规则不写这种行，
因此引用内部的分段会丢失：相邻两行引文合并成一个段落；引用里的列表结束后、后面仍是引用内容时，
那行文字会被并进引用里的列表项。

这不是语法错误，只是版式信息的取舍：读这类文件的人按"每行一段"看引文即可。

## 9. 边界

- 引用内部的分段会丢（§8）；引用里被当作代码写的行不带 `>` 前缀，靠 §4 第 9 条兜住引用的终止。
- 折行（把长行按空格切断）若发生在这一步之前，被切断的列表续行会失去缩进、被切断的表格行会
  破坏表格——与本套规则无关。
- 只做减法：原文本身在某个块边界上没有空行的话，这里也不会补（唯一的补空行是 §6）。
