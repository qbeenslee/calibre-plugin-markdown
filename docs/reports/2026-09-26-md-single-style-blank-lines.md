# `single`（每行一段）段落样式的空行逻辑

日期：2026-09-26

本文只描述**规则本身**：一段已经按标准 Markdown 版式排好（块之间有空行）的文本，在"每行一段"
样式下哪个空行留、哪个删、哪里补。不涉及任何实现。

---

## 1. 目标

- 段落之间的空行全部删掉——每个段落行自己占一行，这就是"每行一段"。
- 但**块的前后各要有一个空行**：围栏代码块、引用块、`* * *`、列表、表格（含表题）、定义
  列表、脚注定义。那些空行是 Markdown 用来认出块结构、或用来结束一个块的语法，缺了文字会
  被读错位置。
- 标题只在**前面**写一个空行（可选开关，§6），后面不写。
- 连续多个空行合并成一个。

这套规则是**保证**，不是留/删：每个块两侧的空行是该有的排版，不是源文碰巧留下的——源文缺
哪一侧就补哪一侧，块在文件首/末则只写有内容的那一侧。

## 2. 行的种类

按 Markdown 的写法把每一行归到一类（引用前缀 `>` 先剥掉再判断）：

| 种类 | 样子 |
|---|---|
| 代码行 | 围栏代码块内的一切（含围栏行本身与其中的空行） |
| 列表行 | 列表项（`- 项`、`1. 项`），以及它之后的缩进行——条目的续行、条目里的第二段、嵌套列表 |
| 表格行 | 表格首行、对齐行（`\|---\|`）、数据行；**要有对齐行才算表格**，只带竖线的正文不算 |
| 表标题行 | 表格上方那行说明性文字（它下面是表格首行才算） |
| 术语行 / 释义行 | 定义列表：术语行，以及它下面的 `: 释义` 行 |
| 脚注定义行 | `[^1]: 正文` |
| 分隔线行 | `* * *`（也含 `- - -`、`___` 与 YAML 文首之外的 `---`） |
| 引用行 | 带 `>` 前缀的行；**以及引用之后不带 `>` 前缀的续行**（引用是读到下一个空行为止） |
| 正文行 | 其余：段落、标题、只带竖线的文字、行内 HTML 行 |

两个容易判错的地方：

- `* * *`（分隔线）不是列表项——它是单独一类，有自己的块；
- 表格必须"首行 + 对齐行"成对出现，否则正文里出现竖线就会被误当成表格。

引用里的行一律归引用行（引用里的列表仍是引用块的一部分）：前后要写空行的是引用，不是里面
的列表。

## 3. 先归块，再在块的两侧写空行

相邻、中间没有空行、且同组的行算**一个块**；空行或另一组的行结束它：

- 表格的首行/对齐行/数据行是一个块，列表的连续条目是一个块，术语行与它下面的 `: 释义`
  行是一个块；
- 中间有空行的两块是两块——列表条目与它的第二段、表格与它上方的表题；
- **引用是例外**：引用内部（含两个引用块相邻）的空行是引用自己的段落分隔，一律删掉，
  所以前后两个引用块合成一个块；
- 围栏内的空行是代码内容，不结束围栏块；
- 标题行自成一块（它下面紧接着的正文是另一块，中间不写空行）。

然后：每个块的前面写一个空行（前面有内容时），后面也写一个（后面有内容时）。两个块相邻
时中间那个空行同时是"前块的后面"和"后块的前面"，只写一个。

## 4. 写的空行（10 处）与不写的后果

| # | 位置 | 不写会怎样 |
|---|---|---|
| 1 | 围栏代码块内（原样保留，含其中的空行） | 代码内容被改 |
| 2 | 围栏代码块前后 | 代码前的一段被并进围栏、后面一段接在围栏行上 |
| 3 | 引用块前后 | 引用是读到下一个空行为止，后面的空行少了会把下面整段正文吞进引用 |
| 4 | 列表块前后 | 列表后的一段被读成最后一个条目的续行；列表前没有空行时，列表根本不被认出 |
| 5 | 列表条目内部（条目第二段的「空行 + 缩进」） | 条目的两段并成一段 |
| 6 | 表格块前后（含表标题与表头之间） | 表格后的一段被读成表格的一行；表格前没有空行时表格不被认出 |
| 7 | 定义列表前后 | 前一段被当成术语、后一段被当成释义的一部分 |
| 8 | 脚注定义块前后 | 定义被并进正文（多数解析器不必须，留着更稳） |
| 9 | `* * *` 前后 | 分隔线前后各成一段更清楚；不写也不算错 |
| 10 | 引用之后不带 `>` 前缀的续行后面 | 那个空行是引用的终止，删掉会把下面整段正文吞进引用 |

## 5. 不写空行的位置（4 处）

| 位置 | 说明 |
|---|---|
| 段落之间 | 含缩进续行、图片行、行内 HTML 行——"每行一段"靠读的人自己分段 |
| 引用块内部 | 引用是"自己的文本"，它内部的空行是引用自己的段落分隔——相邻两个引用块也合成一个块 |
| 标题后面 | ATX 标题自己就开启一个块，下面的正文不会被并进标题 |
| 标题前（可选开关关闭时） | ATX 标题能打断段落 |

## 6. 标题的空行（可选）

「标题前空行」开关打开时，在每个 `#` 标题前写一个空行；文件第一行本身就是标题时不写。
标题后面一律不写——标题是块，但它不需要后面那个空行来结束自己。

## 7. 连续空行

一个位置上的多个空行合并成一个（书籍排版留出的大间距叠在块自身的换行上就会出现）。
围栏代码块内的连续空行不动——那是代码内容。

## 8. 引用块内部：明确不处理

引用里的段落分隔，正确写法是**只含 `>` 的一行**（`> 甲` / `>` / `> 乙`）。本套规则不写这种行，
因此引用内部的分段会丢失：相邻两行引文合并成一个段落；引用里的列表结束后、后面仍是引用内容时，
那行文字会被并进引用里的列表项。

这不是语法错误，只是版式信息的取舍：读这类文件的人按"每行一段"看引文即可。

## 9. 边界

- 引用内部的分段会丢（§8）；引用里被当作代码写的行不带 `>` 前缀，靠 §4 第 10 条兜住引用的
  终止。
- 折行（把长行按空格切断）若发生在这一步之前，被切断的列表续行会失去缩进、被切断的表格行会
  破坏表格——与本套规则无关。
- YAML 文首（`---` … `---`）整段不参与本套规则：它的 `---` 会被读成 `* * *` 分隔线，写空行
  会破坏它。文首之后的第一块照常写空行。
