# 输出插件的空行：哪里写、哪里留、哪里不补

日期：2026-09-26
插件版本：3.20.9（`single` 段落样式的空行规则，见 CHANGELOG 3.20.9）
范围：**输出插件**（`plugin/Markdown/output`）与它用的 `utils/helpers.py`；
输入侧（`input/paragraphs.py`）只作为往返的镜像在 §6 提到。

一份导出的 .md 里的空行只有三个来源：渲染器写下的（block 模式的自然版式）、
`apply_paragraph_style()` 在 `single` 样式下决定留不留、以及 `blank_line_before_heading`
选项插入的。本文把这三处逐条列清楚，并给出每一条「为什么」的实测依据。

---

## 1. 渲染器自己写下的空行（block 模式）

`block`（默认）下这些空行就是标准 Markdown 版式；`single` 下它们是「留还是删」的原料
（§2）。`apply_paragraph_style()` 只做减法，从不新增空行。

| 位置 | 谁写的 | 形状 |
|---|---|---|
| 块级元素 `p/div/h1–h6` | 上游 `MarkdownMLizer.dump_text`：开头 `'\n' + bq + h_tag`、收尾 `'\n'` | 相邻两块之间自然成一个空行 |
| 标题 | `_dump_heading`：`'\n' + bq + '#'×level + ' ' + 文本 + '\n'` | 同上 |
| 列表项 | `_dump_list_item`：行首 `'\n'`（+ 嵌套缩进 + `> ` 前缀 + 子弹） | 每条占一行 |
| 列表结束 | 上游 `</ul>/</ol>` 收尾 `'\n'` | 列表与下一个块之间 |
| 条目的第二个段落 | `_dump_item_paragraph`：`'\n\n' + '\t'×深度` | **空行 + 缩进**，留在条目内 |
| 表格 | `_render_table`：首 `'\n'`、标题 `'*标题*\n\n'`、每行 `'\n'`、末 `'\n'` | 表格前后各一个空行 |
| 定义列表 | `_dump_definition_list`：首 `'\n'`、每对 `': 释义\n\n'` | 术语行前、释义行后 |
| 脚注定义块 | `_render_footnotes`：首 `'\n'`、每条 `'[^n]: 正文\n'`、末 `'\n'` | 块前 |
| 引用块 | `_dump_blockquote`：结尾补 `'\n'`；tail 文本前再补 `'\n'` | 引用结束处 |
| 软场景分隔 | 上游 `dump_text` 与 `_css_margin_break`：按 CSS margin 算 `'\n\n'×ems` | 块上/下方，可能连着好几个空行 |
| 围栏代码块 | `_dump_fenced_pre`：`'\n```lang\n'` … `'\n```\n'` | **围栏内的空行是内容** |
| spine 文件之间 | `mlize_spine`：每个文件后 `'\n\n'` | 章与章之间 |
| 文档骨架 | `render_yaml_front_matter` 尾 `'---\n\n'`、`_cover_markdown` `'![Cover](…)\n\n'`、`render_toc_block` `'## 目录\n\n条目…\n'` | YAML 后、封面后、目录标题后 |
| `<hr>` | 上游：`'\n* * *'` | **不带空行** |

清理与不清理：上游 `tidy_up()` 只清「空白行里的空格」、把 7 个以上换行压成 6 个、去掉
文件首尾空白——**不合并 2~6 个换行**，所以 block 模式的文本里会出现空行串（§2 的合并规则
正是对着它来的）。

## 2. `single` 样式：留 / 删 / 插 / 合并

### 2.1 留（这些空行不是段落分隔）

| # | 位置 | 不留会怎样 | 谁需要 |
|---|---|---|---|
| 1 | **围栏代码块内**（整段原样） | 代码内容被改 | 两边都要（内容是代码） |
| 2 | **引用块结束处** | 下面一行被吞进引用（lazy continuation） | 两边都要 |
| 3 | **列表块前后**（条目之间、条目与前后文之间） | 后一段被读成最后一个条目的续行；python-markdown 根本不认段落里的列表 | 两边都要 |
| 4 | **列表条目内部**（条目第二段的「空行 + 缩进」） | 条目两段并成一段 | 两边都要 |
| 5 | **表格块前后**（含上方 `*标题*` 行与表头之间） | 后一段被读成表格的一行（GFM 规范 Example 202 就是这个行为）；python-markdown 不认段落里的表格 | 两边都要 |
| 6 | **定义列表前后**（术语行前、`: 释义` 行后） | 前一段被读成 `<dt>`、后一段被读进 `<dd>` | python-markdown（GFM 无定义列表语法） |
| 7 | **脚注定义块前** | 定义被并进正文（防御性） | python-markdown 实测不必须，留着更稳 |
| 8 | **结构下方紧跟引用行时**（`- 项` / 表格行下面那行 `>`） | 引用打断得了段落、打断不了列表项，那行 `>` 被读成条目的续行 | 两边都要（真书 394） |
| 9 | **引用之后不带 `>` 前缀的正文行**（引用里的 `<pre>` 就是这么写的）后面的空行 | 空行是引用的终止，删掉会把下面整段正文吞进引用 | 两边都要（真书 427） |

### 2.2 删（这些确实是段落分隔，或本来就不需要）

| 位置 | 说明 |
|---|---|
| 段落之间 | 包括缩进续行、图片行、行内 HTML 行——「每行一段」靠读者/读取器自己分段 |
| **引用块内部** | 引用是"自己的文本"，它内部的空行是引用的段落分隔（本次不动，见 §5） |
| 围栏代码块前后 | 围栏能打断段落，`single` 在那里保持紧凑 |
| `* * *` 前后 | 分隔线能打断段落（CommonMark §4.1） |
| **进入引用处**（正文行 → 引用行） | 引用能打断段落（CommonMark §5.1 Example 223） |
| 标题前（选项关闭时） | 标题能打断段落（CommonMark §4.2） |

### 2.3 插（只有一处，来自选项）

`blank_line_before_heading`（默认开）：`single` 下在每个 `#` 标题前补一个空行，**文件
第一行的标题不补**；`block` 下无效。这是唯一会新增空行的地方。

### 2.4 合并

渲染器留下的空行串（软场景分隔叠上块自身的换行，§1）合并成**一个**；围栏代码块内的
空行串不动（那是代码内容）。实测：真书 371 原来有 9 处 4 连空行，现在为 0（代码围栏内的
除外）。

## 3. 判定是怎么做的

`utils/helpers.py` 两步：

1. `_classify_lines(lines, following)` —— 逐行标出**结构**与**是否引用行**：列表项与条目
   续行（`_LIST`）、表格行与上方标题行（`_TABLE` / `_CAPTION`）、定义列表的术语行与 `: ` 行
   （`_DEF_TERM` / `_DEF_ITEM`）、脚注定义行（`_FOOTNOTE`）、围栏内的行（`_FENCED`）、引用行
   （`_QUOTE`，含引用里不带前缀的 lazy 行），其余是正文行（`_TEXT`）。表格要有「首行 + 对齐行」
   才算表格（只带竖线的正文行不算）；`* * *` 先按分隔线认，不当列表项。
2. `_keeps_a_blank_line(previous, following)` —— 空行两侧任一侧是结构就留；上一行是引用行
   时，只在「下一行不是引用行」时留。

`_STRUCTURE_KINDS` = 列表 / 表格 / 表格标题 / 定义列表术语 / 定义列表释义 / 脚注定义。
顺序要点：`previous.quoted` 的判定排在结构判定之前——这就是「引用内部一律不动」的实现
（§5）。

## 4. 为什么这些地方必须留：实测

- `scripts/probe_single_style_blank_lines.py`：24 种「块结构 + 前后正文」的 block 版过一遍
  `apply_paragraph_style(text, 'single')`，再用 **python-markdown**（输入插件读 .md 用的同一个
  解析器，扩展 `footnotes, tables, fenced_code, def_list, attr_list, toc`）渲染两边比对 HTML →
  **24/24 一致**。改前 12/24 被破坏。
- GFM 侧用 markdown-it 复核：表格后跟正文行 → 被当成表格的一行（与 GFM 规范 Example 202
  一致）；列表后跟正文行 → 被吞进最后一个条目；围栏代码、`* * *`、ATX 标题 → 都能打断段落，
  不需要空行。
- `scripts/verify_single_style_blank_lines.py`：371 / 394 / 427 / 818 / 17 / 919 六本真书各转
  block 与 single，渲染后比对**块结构指纹**（列表/表格/定义列表/代码/标题/引用的元素及其文本，
  引用按合并后的文本计）→ **6/6 一致**，同时 single 版空行明显更少（919：18132 → 96）。

## 5. 引用内部：明确不做

引用里的段落分隔要写成**只含 `>` 的行**（输入侧 `input/paragraphs.py` 的 `_prefix_quote_lines`
就是这么写的）。输出侧本次不写这种行，因此：

- `> 甲` / `> 乙` 之间的空行照旧删掉（有测试锁住）；
- 引用里的列表/表格结束、后面仍是引用内容时，那行正文会被并进引用里的列表项——**block 模式
  那里也只是普通空行**，属既有问题，未列入本次范围；
- 往返不受影响：输入插件读到 single 文件时会按"引用是自己的文本"重新排版，把引用内分段补成
  `>` 行。

## 6. 输入侧的镜像（往返）

输入插件 `restructure_paragraphs(text, 'single')` 做的是相反方向：给每个正文行后面补空行
（标题行也补），引用块整体按"引用是文本"递归重排后用 `>` 行分段，代码块/列表/表格/定义列表
不拆。所以输出侧在 `single` 下删掉的引用内分段，插件自己读回来时会补上；而输出侧删掉的段落
空行，也是靠这一步恢复的。

## 7. 已知边界

- **引用内分段**会丢（§5）。
- **引用里的 `<pre>` 不带 `>` 前缀**（渲染器行为），靠 §2.1 第 9 条兜住引用的终止；引用里的
  表格同样不带前缀（block 模式也一样，未处理）。
- **折行先于段落样式执行**：`max_line_length > 0` 时正文按空格折行，折开的列表续行不带缩进、
  折开的表格行会破坏表格——与本步无关，该功能默认关闭。
- **只做减法**：`single` 从不往正文里插入空行（唯一的插入是 `blank_line_before_heading`），
  所以 block 模式文本本身缺空行的地方，single 也不会补。
