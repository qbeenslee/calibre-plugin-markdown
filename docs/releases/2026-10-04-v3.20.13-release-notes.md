## 中文

本次是 3.20.10～3.20.13 四个版本的合并发版：两处修复、两处输出格式改进。最值得注意的是 3.20.13——GUI / 批量转换在 **MD → EPUB** 方向连转多本带图的书时，可能把**别的书的图片**装进当前的 EPUB；3.20.12 修掉了块尾 `<br>` 把强调符推到下一行的问题。输出侧，`single` 样式改为一律保证块前后各有一个空行（3.20.10），`<hr>` 统一写成 `***`（3.20.11）。不涉及设置项增删。

### 修复

- **MD → EPUB 不再串书：跨书同名图片只认本书目录**（3.20.13）
  GUI / 批量转换会把书的格式副本放进 calibre 的**会话级临时目录**再交给 TXT Input——这个目录就是 TXT Input 的 `base_dir`，一次会话里所有转换的输入副本都躺在里面；插件暂存的图库图片原来也写在这个共享目录里，转换结束不删除。于是先转书 B、再转书 A 时，A 里 `images/000001.png` 这样的引用会先命中 B 留下的同名文件——引用「已经就在输入旁边」，插件不再从 A 的书目录取图，A 的 EPUB 里装的其实是 B 的图片（两本书同位置导出的图片内容不同时必现）。这不只是显示问题，而是**内容错误**。
  现在：每次转换的暂存图片写在共享目录里的一个随机子目录（`md-stage-*`），引用改指向该副本，转换结束（含失败）即整目录删除；书目录已知时（GUI / 批量注入 metadata opf 的场景）**只认书目录里的图片**，共享目录里的同名文件一概不算本书的图，找不到就按「无法解析」记入转换日志，不再悄悄用别人的图。远程图片下载同样落在该子目录，命名避让与清理一并对齐；并发的多本转换各写各的子目录，互不覆盖、互不相读。
  验收：新增 `scripts/verify_md_cross_book_images.py` 真机脚本（复刻 GUI 两步：共享临时目录 + 各自注入 opf；两本书都引用 `images/000001.jpg` 且内容不同；先转 B 再转 A）——修复前共享目录残留 B 的 `images/`、A 的 EPUB 装的是 B 的图（3 项 FAIL）；修复后 B 用 B 的图、A 用 A 的图、两轮转换后共享目录只剩两份 md 副本（4/4 PASS）。单元测试新增 4 项回归，`plugin/tests` 全量 521 passed（修复前 517）。

- **块尾 `<br>` 不再把强调符推到下一行**（3.20.12）
  EPUB → MD 时，块级内容末尾的 `<br>` 作为冗余换行省略：`<blockquote><p><em>文字<br/></em></p></blockquote>` 现在输出 `> *文字*`，不再输出 `> *文字  ` 后再跟一行孤立的 `*`。位于块中间的 `<br>` 仍是 Markdown 硬换行（行尾两个空格 + 换行），在引用里还会为续行补上 `> `，保证每一行都属于引用。
  验收：新增三项回归场景，单元测试 517 passed；calibre 自带运行时的块引用探针 0 failure。

### 改进

- **`<hr>` 统一写成 `***`**（3.20.11）
  两者是同一个分隔线（python-markdown 读回都是 `<hr>`），但 `* * *` 一眼看去像三个空列表项，`***` 是其余 Markdown 生态的写法。只改标记本身：元素前后的空行（CSS 边距要的软场景分隔、块自身的换行）与尾部文字照旧由上游写出，输出形如「空行 / `***` / 空行」，`block` 与 `single` 两种段落样式一致。空行规则里的分隔线识别（`_THEMATIC_LINE_RE`）与输入侧读 `.md` 的 `_THEMATIC_RE` 本来就同时认两种写法，旧文件照常读、结果不变。
  验收：新增 `plugin/tests/test_thematic_break.py`；四本带 `<hr>` 的真书 213 处 `* * *` 全部变成 `***`，逐本空行数不变（371/394/427/818），六本真书块结构指纹 6/6 一致，单元测试 514 passed。

- **`single`（每行一段）样式下块前后一律各留一个空行**（3.20.10）
  覆盖围栏代码块、引用块、`* * *` 分隔线、列表（含条目第二段）、表格（含表题）、定义列表、脚注定义：每一个都在前面和后面各写一个空行，源文缺哪一侧就补哪一侧，多个空行合并成一个，块在文件首/末则只补有内容的那一侧。之前只有引用块是单侧的（`* * *` 与围栏代码块两侧都不补），现在三者与列表/表格等一致。引用块**内部**的空行（含两个引用块相邻时中间那个）照旧删掉。
  实现改为先把内容行按组归成块（`_content_blocks`：相邻且中间无空行的同组行算一个块，围栏内的空行是内容，引用行一律归引用组，标题行自成一块），再按块在两侧写空行（旧的逐行判断 `_keeps_a_blank_line` 删除）。YAML 文首（`---` … `---`）整段切出原样写回——它的 `---` 会被读成 `* * *` 分隔线、补空行会破坏它；斜体引用块收尾那个单独成行的 `*` 归入它所属的块，否则补进去的空行会把强调拆开。标题保持原逻辑：只有前面补空行（可选开关），后面不补。
  验收：单元测试 512 passed；`scripts/verify_single_style_blank_lines.py` 六本真书块结构指纹 6/6 与 `block` 版一致。

### 升级

下载 `Markdown.zip` → calibre「首选项 → 插件 → 从文件加载」（覆盖同名插件）→ 重启 calibre；macOS 也可在本仓库根目录执行 `./install.sh`（打包并复制到 `~/Library/Preferences/calibre/plugins/Markdown.zip`）。需要 calibre ≥ 6.0.0；旧设置无需改动。
如果你曾用 GUI / 批量转换在 **MD → EPUB** 方向连转多本带图的书，3.20.13 修复的串图问题可能已影响过旧的转换结果，建议升级后重转一次。

## English

This release rolls up v3.20.10 – v3.20.13: two fixes and two output-format improvements. The headline is 3.20.13 — GUI and batch conversion could put **another book's images** into the EPUB you were converting (MD → EPUB); 3.20.12 fixes a trailing `<br>` that pushed an emphasis marker onto its own line. On the output side, `single` now always guarantees a blank line on each side of a block (3.20.10), and `<hr>` is written as `***` (3.20.11). No preference was added or removed.

### Fixes

- **MD → EPUB no longer mixes images across books: only the book's own directory counts** (3.20.13)
  GUI and batch conversion place a copy of the book's format file into calibre's **session-level temporary directory** and hand it to TXT Input — that directory *is* TXT Input's `base_dir`, and every conversion in the session drops its input copy there. The plugin's staged library images were written into that same shared directory too, and were never deleted when a conversion finished. So after converting book B and then book A, a reference like `images/000001.png` inside A would first hit the same-named file B had left behind: to the plugin the image was "already sitting next to the input", so it never fetched it from A's own book directory, and A's EPUB shipped with **B's images** (guaranteed whenever the two books' exported images differ). That is not a cosmetic issue but wrong content.
  Now each conversion stages its images into a random subdirectory (`md-stage-*`) of the shared directory, references point at that copy, and the whole directory is removed when the conversion finishes (failure included). When the book directory is known (GUI, and batch runs that inject a metadata opf), **only images from the book directory are accepted**; a same-named file in the shared directory is never treated as this book's image — if nothing is found, the reference is logged as unresolvable instead of silently substituting someone else's picture. Remote image downloads land in the same subdirectory, with naming avoidance and cleanup aligned, and concurrent conversions keep to their own subdirectories.
  Verified: the new on-device script `scripts/verify_md_cross_book_images.py` replicates the two GUI steps (shared temp dir + per-book injected opf; both books reference `images/000001.jpg` with different content; B converted before A) — before the fix: B left its `images/` behind and A's EPUB contained B's image (3 FAIL); after: B uses B's image, A uses A's image, and only the two md copies remain in the shared directory (4/4 PASS). Four new unit regression tests; the full `plugin/tests` run is 521 passed (517 before).

- **A trailing `<br>` no longer pushes an emphasis marker onto its own line** (3.20.12)
  On EPUB → MD, a `<br>` at the end of block-level content is dropped as a redundant line break: `<blockquote><p><em>文字<br/></em></p></blockquote>` now renders as `> *文字*` instead of `> *文字  ` followed by a lone `*`. A `<br>` in the middle of a block still emits a Markdown hard break (two trailing spaces plus a newline), and inside a quote the continuation line receives its `> ` so every line belongs to the quote.
  Verified: three new regression scenarios, 517 unit tests pass, and a blockquote probe on calibre's own runtime reports 0 failures.

### Improvements

- **`<hr>` is written as `***`** (3.20.11)
  Both spellings are the same separator (python-markdown reads either back as `<hr>`), but `* * *` reads like three empty list items while `***` is the rest of the Markdown ecosystem's spelling. Only the marker itself changes: the blank lines around the element (the soft scene separation CSS margins ask for, plus the block's own line breaks) and any trailing text still come from upstream, so the output looks like "blank line / `***` / blank line", identically for the `block` and `single` paragraph styles. The thematic-break recognition used by the blank-line rules (`_THEMATIC_LINE_RE`) and the input side's reader for `.md` (`_THEMATIC_RE`) already accept both, so existing files are read back unchanged.
  Verified: new `plugin/tests/test_thematic_break.py`; in four real books all 213 `* * *` became `***` with per-book blank-line counts unchanged (371/394/427/818), six real books match on block-structure fingerprints 6/6, and 514 unit tests pass.

- **`single` always guarantees one blank line on each side of a block** (3.20.10)
  Covered blocks: fenced code blocks, quote blocks, `* * *` thematic breaks, lists (including an item's second paragraph), tables (including captions), definition lists and footnote definitions. Each one now gets a blank line before and after, whichever side the source is missing gets filled in, runs of blank lines collapse to one, and a block at the very start or end of the file only gets the side that has content. Previously only quote blocks were single-sided and `* * *` / fenced code blocks had neither side; now all three match lists and tables. Blank lines *inside* a quote (including the one between two adjacent quote blocks) are still removed.
  The implementation no longer decides line by line whether a blank line survives (the old `_keeps_a_blank_line` is gone). Content lines are first grouped into blocks (`_content_blocks`: adjacent same-group lines with no blank line in between form one block; blank lines inside fences are content, not separators; quote lines always belong to the quote group; heading lines form their own block), and blank lines are then written around the blocks. YAML front matter (`---` … `---`) is cut out and written back verbatim — its own `---` would be read as a `* * *` break and the extra blank lines would break it; the lone line holding the closing `*` of an italic quote block belongs to that block, otherwise the inserted blank line would split the emphasis. Headings keep the old rule: a blank line before (optional switch), none after.
  Verified: 512 unit tests pass; `scripts/verify_single_style_blank_lines.py` matches block-structure fingerprints 6/6 against the `block` style on six real books.

### Upgrading

Download `Markdown.zip` → calibre *Preferences → Plugins → Load plugin from file* (overwrite the existing one) → restart calibre. On macOS you can also run `./install.sh` from the repo root (builds and copies to `~/Library/Preferences/calibre/plugins/Markdown.zip`). Requires calibre ≥ 6.0.0; existing settings carry over unchanged.
If you have converted several illustrated books in a row in the **MD → EPUB** direction from the GUI or via batch conversion, the cross-book image mix-up fixed in 3.20.13 may already have affected those results — it is worth converting them once more after upgrading.
