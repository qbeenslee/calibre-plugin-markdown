## 中文

本次是 3.20.5～3.20.9 五个版本的合并发版，全部集中在 **Markdown 输出的结构保真** 与 **Markdown 输入的资源去重**，另有一次纯内部重构。行为变化都在转换结果上，不涉及设置项增删。

### 修复

- **`single`（每行一段）样式不再删掉块结构周围的空行**（3.20.9）
  那些空行不是段落分隔，删掉后 Markdown 会把块前后的文字读成块的一部分：列表后的一段被吞成最后一个条目的 lazy continuation 行、表格后的一段被吞成表格的一行（GFM 规范 Example 202 即此行为）、定义列表后的一段被吞进 `<dd>`、引用块结束处的后一行被吞进引用；输入插件读 `.md` 用的 python-markdown 根本不认段落里的列表与表格，所以列表、表格**前**的空行同样保留。
  保留范围：列表前后与条目内部（条目的第二段）、表格前后（含表格上方 `*标题*` 行与表头之间）、定义列表前后、脚注定义块前；段落之间的空行照旧全部删除；围栏代码块内、引用块结束处两条既有规则不变；`* * *`、围栏代码块前后、进入引用处仍不补空行（`single` 保持紧凑）。
  实现改为对整份文件逐行分类（`utils/helpers.py` 的 `_classify_lines`），空行两侧任一侧是这些结构就留下，同一处的空行串合并成一个；结构下方紧跟引用行时也要留空行（引用打断得了段落，打断不了列表项），引用之后不带 `>` 前缀的正文行仍算引用、它后面的空行是引用的终止。
  验收：24/24 结构案例与 `block` 版渲染一致，6 本真书块结构指纹 6/6 一致，单元测试 505 passed。

- **列表项文字不再掉到子弹下一行**（3.20.7）
  书把条目文字包在 `<p>` 里时，上游曾把那个 `<p>` 当独立块渲染，输出成 `- ` + 换行 + 文字（条目成了空项）。现在列表项里的 `<p>`/`<div>` 包裹是透明的，文字直接接在 `- ` 后面；条目里的第二个段落、引用块（`- > 引文`）、嵌套列表照旧各占一行并缩进在条目下；条目前后用于缩进的空白不再写进行尾。

- **章节标题不再出现层级重复/拆行**（3.20.6）
  `<h2><span>第0001章</span><br/>我成了岳不群</h2>` 原来输出 `## ### 第0001章` 加孤立行。现在标题内容一律按行内文本渲染：`<br>` 变空格、块级子元素与嵌套标题压成一行（嵌套标题只保留更深的那一级）、不写出从标题继承来的 `**`/`*`；链接/图片/sup/sub/code 等行内语法照旧。层级仍由输入侧与转换规则决定（h1→`#` … h6→`######`）。

- **MD → EPUB 时同一张图片只打包一份**（3.20.5）
  内置 TXT Input 对每个 `<img>` 都调一次 `shift_file` 并另起文件名，引用 N 次就塞 N 份副本。现在相同内容的图片只写一份，所有引用指向它：样本《圣女母亲》引用同一张图 110 次，13.1 MB / 110 份 → 1.5 MB / 1 份。

### 改进

  `markdownml_enhanced.py` 从 1446 行降到 303 行，只留类状态、每本书的生命周期与 `dump_text` 分派；列表、引用与图、标题、脚注、表格、链接与图片、目录与文首、行内标记与代码、文本转义九个渲染域各成一个 mixin，放进 `output/renderers/`，共享常量与纯函数集中在 `renderers/primitives.py`。60 个方法经 AST 逐字比对无差异，生成的 Markdown 与旧版一致，打包与设置面板不受影响。

## English

This release rolls up v3.20.5 – v3.20.9. Everything is about **structural fidelity of the Markdown output** and **asset deduplication on the input side**, plus one internal refactor. No preference was added or removed.

### Fixes

- **`single` (one line per paragraph) no longer strips the blank lines around block structures** (3.20.9)
  Those blank lines are not paragraph separations — removing them makes Markdown read the surrounding text as part of the block: a paragraph after a list becomes the last item's lazy continuation line, a line after a table becomes a table row (GFM spec Example 202), a paragraph after a definition list is swallowed into `<dd>`, and the line closing a quote block is pulled into the quote. python-markdown — the same parser the input plugin uses to read `.md` — does not accept lists or tables inside a paragraph, so the blank line *before* a list or table is kept as well.
  Now kept: around lists (and between an item's own paragraphs), around tables (including between a `*caption*` line above and the header row), around definition lists, before footnote definitions; blank lines *between paragraphs* are still removed; the two existing rules (inside fenced code blocks, and the one that ends a quote block) are unchanged; `* * *`, fenced code blocks and the entry into a quote still get no extra blank line, keeping `single` compact.
  Implemented as a whole-file line classification (`_classify_lines` in `utils/helpers.py`): a blank line is kept when either neighbour is one of these structures, and runs of blank lines collapse to one (untouched inside fences). A quote line right below a block also gets its blank line (a quote can interrupt a paragraph but not a list item), and body lines without the `>` prefix still count as part of the quote, so the blank line after them closes it.
  Verified: 24/24 structural cases render identically to the `block` style, block-structure fingerprints match on 6/6 real books, 505 unit tests pass.

- **List item text stays on the bullet line** (3.20.7)
  Books that wrap item text in `<p>` used to be rendered as a standalone block, producing `- ` followed by a newline and the text (an empty item with the text falling out of the list). `<p>`/`<div>` wrappers inside a list item are now transparent and the text follows `- ` directly. A second paragraph, a quote (`- > quote`) or a nested list inside an item still gets its own indented line, and the indentation whitespace around items is no longer written at line ends.

- **Chapter headings no longer duplicate their level or split into lines** (3.20.6)
  `<h2><span>第0001章</span><br/>我成了岳不群</h2>` previously produced `## ### 第0001章` plus an orphaned line. Heading content is now rendered as inline text: `<br>` becomes a space, block-level children and nested headings are flattened to one line (only the deeper heading level is kept), and the inherited `**`/`*` markers are not emitted. Links, images, `sup`/`sub`/`code` and other inline syntax are preserved. The level itself still comes from the input side and the conversion rules (h1→`#` … h6→`######`).

- **MD → EPUB packs a repeated image only once** (3.20.5)
  The built-in TXT Input calls `shift_file` for every `<img>` and each call invents a new filename, so N references embedded N copies. Images with identical content are now written once and every reference points to that copy: the sample book *圣女母亲* references the same image 110 times — 13.1 MB / 110 copies → 1.5 MB / 1 copy.

### Improvements

- **Output renderer split by rendering domain** (3.20.8, internal refactor)
  `markdownml_enhanced.py` shrank from 1446 to 303 lines, keeping only class state, the per-book lifecycle and the `dump_text` dispatch. Nine rendering domains (lists, quotes and figures, headings, footnotes, tables, links and images, TOC and front matter, inline markup and code, text escaping) now live as mixins under `output/renderers/`, with shared constants and pure functions in `renderers/primitives.py`. All 60 methods were moved verbatim (verified by AST diff), so the generated Markdown is unchanged; packaging and the preferences dialog are unaffected.

### Docs

- README now shows the conversion dialog and the "customize plugin" dialog screenshots for both directions (zh-CN UI).
- Added `docs/reports/2026-09-23-md-output-format-rules.md`, `docs/reports/2026-09-26-md-single-style-blank-lines.md` and `docs/specs/2026-09-26-output-renderer-split(-plan).md`.
- The "paragraph style" help text in the conversion dialog now describes which blank lines `single` keeps.

### Upgrading

Download `Markdown.zip` → calibre *Preferences → Plugins → Load plugin from file* (overwrite the existing one) → restart calibre. On macOS you can also run `./install.sh` from the repo root (builds and copies to `~/Library/Preferences/calibre/plugins/Markdown.zip`). Requires calibre ≥ 6.0.0; existing settings carry over unchanged.
